Python throws UnboundLocalError because x is treated as a local variable inside the function but is referenced before assignment.
Python treats x as a local variable because you are assigning a value to it.
But before assigning, Python tries to evaluate:
x + 1
It looks for local x, but it has not been defined yet, so it throws the error.

x = 10

def foo():
    global x
    x = x + 1

gen = (i * i for i in range (3))
print(list(gen))
print(list(gen))

---explanation
This creates a generator object.
Generators produce values one by one and get exhausted after use.
Values generated:
0*0 = 0
1*1 = 1
2*2 = 4
Step 2: First Print
print(list(gen))
The generator is converted to a list, so it produces all values.
Output:
[0, 1, 4]
After this step, the generator is exhausted (all values already consumed).
Step 3: Second Print
print(list(gen))
Now the generator has no values left, so it returns an empty list.
Output:
[]
Final Output:
[0, 1, 4]
[]
Generators can be iterated only once. After consumption, they become empty.
If you want reusable values
Use a list instead:
gen = [i * i for i in range(3)]
print(list(gen))
print(list(gen))
Output:
[0, 1, 4]
[0, 1, 4]

A generator gets exhausted after the first iteration, so the second call returns an empty list.

[0,1,4]
[0,1,4]

funcs = []
for i in range(3):
        funcs.append(lambda: i)

print([f() for f in funcs])
---
Output
[2, 2, 2]
Why does this happen?
The lambda function does not store the value of i at the time it is created.
Instead, it references the variable i itself (this is called late binding).
After the loop finishes:
i = 2
All lambda functions refer to the same variable i, whose final value is 2.
So when the lambdas execute:
lambda: i → 2
lambda: i → 2
lambda: i → 2
Result:
[2, 2, 2]
Visual Idea
During loop:
lambda → i
lambda → i
lambda → i
After loop:
i = 2
So all lambdas return 2.
---
Late Binding Meaning
Python does not store the value of variables when lambda is created.
Instead it stores a reference to the variable.
So when the function runs later, it checks the current value.
Python closures use late binding, 
meaning lambda functions capture the variable reference instead of its value. 
Since the loop finishes with i = 2, all lambdas return 2.

----
SELECT 
    c.name,
    COUNT(o.order_id) AS total_orders
FROM customers18 c
LEFT JOIN orders18 o
    ON c.customer_id = o.customer_id
    AND EXTRACT(MONTH FROM o.order_date) <> 6
